# SonarQube Local Setup with Docker Compose

This guide documents the local SonarQube setup for a Java / Spring Boot
project using Maven on Linux.

## 1. Prerequisites

Install Docker, Docker Compose, Java, and Maven.

Verify the installations:

``` bash
docker --version
docker compose version
java -version
mvn -version
```

Docker installation instructions:
<https://docs.docker.com/engine/install/>

## 2. Configure Linux for Elasticsearch

SonarQube uses Elasticsearch, which requires a sufficiently high
`vm.max_map_count` value.

Check the current value:

``` bash
sysctl vm.max_map_count
```

Set it to `524288`:

``` bash
sudo sysctl -w vm.max_map_count=524288
```

Make the setting persistent across reboots:

``` bash
echo 'vm.max_map_count=524288' | sudo tee /etc/sysctl.d/99-sonarqube.conf
sudo sysctl --system
```

Verify:

``` bash
sysctl vm.max_map_count
```

Expected value:

``` text
vm.max_map_count = 524288
```

## 3. Check available disk space

Check filesystem and Docker usage before starting SonarQube:

``` bash
df -h
docker system df
```

During the initial setup, Elasticsearch failed because the disk
watermark was exceeded. The logs included messages similar to:

``` text
high disk watermark [90%] exceeded
no_shard_available_action_exception
Elasticsearch health RED
```

If you need to reclaim space, inspect Docker usage first. You can remove
unused build cache and unused images:

``` bash
docker builder prune
docker image prune -a
```

These commands can remove cached build data and images that are not
currently used. Do not casually prune Docker volumes: volumes may
contain persistent application data.

Check disk space again:

``` bash
df -h
docker system df
```

## 4. Create the Docker Compose file

Create a directory for SonarQube and enter it:

``` bash
mkdir sonarqube
cd sonarqube
```

Create `docker-compose.yml`:

``` bash
nano docker-compose.yml
```

Add this configuration:

``` yaml
services:
  sonarqube:
    image: sonarqube:community
    container_name: sonarqube
    ports:
      - "9000:9000"
    volumes:
      - sonarqube_data:/opt/sonarqube/data
      - sonarqube_extensions:/opt/sonarqube/extensions
      - sonarqube_logs:/opt/sonarqube/logs
    restart: unless-stopped

volumes:
  sonarqube_data:
  sonarqube_extensions:
  sonarqube_logs:
```

The named volumes preserve SonarQube data, extensions, and logs when the
container is stopped or recreated.

## 5. Start SonarQube

Run this from the directory containing `docker-compose.yml`:

``` bash
docker compose up -d
```

Check container status:

``` bash
docker compose ps
```

Follow the startup logs:

``` bash
docker compose logs -f sonarqube
```

Wait for SonarQube to finish starting before opening the web interface.

## 6. Open SonarQube

Open:

<http://localhost:9000>

On a fresh installation, the initial credentials are:

``` text
Username: admin
Password: admin
```

SonarQube will prompt you to change the default password.

## 7. Create a SonarQube project

1.  Sign in to SonarQube.
2.  Choose **Create a project**.
3.  Create the project manually if prompted.
4.  Enter a project name and project key.
5.  Finish creating the project.

**Important:** The project key in the Maven analysis command must
exactly match the key shown in SonarQube. Do not assume an example
project key is your actual key.

## 8. Generate an analysis token

Generate a token using the SonarQube project setup wizard's **Locally**
instructions, or from **My Account → Security**.

Store the token securely. Do not commit it to Git or place it in
`pom.xml`.

Export it in the terminal:

``` bash
export SONAR_TOKEN='your-actual-token'
```

Check that the variable is set without printing the token:

``` bash
echo ${SONAR_TOKEN:+TOKEN_IS_SET}
```

Expected output:

``` text
TOKEN_IS_SET
```

The environment variable normally lasts only for the current shell
session.

## 9. Run analysis on the Spring Boot Maven project

Navigate to the directory containing your project's `pom.xml`:

``` bash
cd /path/to/your/backend
```

Use the exact Maven command generated by the SonarQube project setup
wizard. It will include the correct server URL, project key, and scanner
configuration.

A general example is:

``` bash
mvn clean verify \
  org.sonarsource.scanner.maven:sonar-maven-plugin:5.8.0.7211:sonar \
  -Dsonar.host.url=http://localhost:9000 \
  -Dsonar.projectKey=YOUR_PROJECT_KEY \
  -Dsonar.token="$SONAR_TOKEN"
```

Replace `YOUR_PROJECT_KEY` with the exact key from your SonarQube
project. The plugin version in this example is the version used in the
earlier troubleshooting; prefer the command generated by your own
SonarQube instance.

What the command does:

-   `mvn clean` removes previous build output.
-   `mvn verify` builds and verifies the project, including configured
    tests.
-   The Sonar Maven plugin submits the analysis.
-   `sonar.host.url` points to the local SonarQube server.
-   `sonar.projectKey` identifies the project.
-   `sonar.token` authenticates the analysis request.

## 10. Verify the analysis

After Maven completes successfully:

1.  Open <http://localhost:9000>.
2.  Go to **Projects**.
3.  Open your project.
4.  Review the analysis dashboard.

Depending on the project and configuration, the dashboard can show bugs,
vulnerabilities, code smells, security hotspots, duplication, coverage,
and Quality Gate status.

## 11. Optional: Add JaCoCo test coverage

SonarQube needs a coverage report from a coverage tool such as JaCoCo to
report test coverage.

Add this plugin inside the `<plugins>` section of your Maven `pom.xml`:

``` xml
<plugin>
    <groupId>org.jacoco</groupId>
    <artifactId>jacoco-maven-plugin</artifactId>
    <version>0.8.12</version>
    <executions>
        <execution>
            <goals>
                <goal>prepare-agent</goal>
            </goals>
        </execution>
        <execution>
            <id>report</id>
            <phase>verify</phase>
            <goals>
                <goal>report</goal>
            </goals>
        </execution>
    </executions>
</plugin>
```

Run:

``` bash
mvn clean verify
```

The default XML report location is:

``` text
target/site/jacoco/jacoco.xml
```

SonarQube can import this report during analysis.

## 12. Troubleshooting

### SonarQube does not start: disk watermark exceeded

Check:

``` bash
df -h
docker system df
docker compose logs sonarqube
```

Free up disk space if the filesystem is nearly full, then restart:

``` bash
docker compose restart sonarqube
```

### Elasticsearch reports RED health or unavailable shards

Logs may contain:

``` text
no_shard_available_action_exception
```

In the setup described here, this occurred alongside the disk watermark
error. Check disk space and the SonarQube logs before trying other
changes.

### Maven says the project does not exist or analysis is unauthorized

An error may say:

``` text
You're not authorized to analyze this project or the project doesn't exist on SonarQube and you're not authorized to create it.
```

Check the following:

1.  The project exists in SonarQube.
2.  The project key in the Maven command exactly matches the project key
    in SonarQube.
3.  The token is valid and has not expired.
4.  The token belongs to a user with **Execute Analysis** permission for
    the project, or is an appropriately scoped project analysis token.

Validate the token:

``` bash
curl -u "$SONAR_TOKEN:" \
  http://localhost:9000/api/authentication/validate
```

Expected response:

``` json
{"valid":true}
```

A valid token does not by itself prove that the user has permission to
analyze the project.

## 13. Useful Docker Compose commands

Run these from the directory containing `docker-compose.yml`:

  Task                                    Command
  --------------------------------------- ------------------------------------
  Start in background                     `docker compose up -d`
  Stop the container                      `docker compose stop`
  Start a stopped container               `docker compose start`
  Restart                                 `docker compose restart`
  View status                             `docker compose ps`
  Follow logs                             `docker compose logs -f sonarqube`
  Stop and remove the container/network   `docker compose down`
  Pull the configured image               `docker compose pull`

**Volume warning:** `docker compose down` preserves named volumes by
default. Avoid `docker compose down -v` unless you intentionally want to
delete the SonarQube volumes and their stored data.

## Quick workflow for future runs

Once the Compose setup and SonarQube project are created:

1.  Start SonarQube:

    ``` bash
    docker compose up -d
    ```

2.  Set the token in your terminal:

    ``` bash
    export SONAR_TOKEN='your-actual-token'
    ```

3.  Navigate to your Maven project:

    ``` bash
    cd /path/to/your/backend
    ```

4.  Run the exact Maven analysis command generated by SonarQube.

5.  Review the results at <http://localhost:9000>.
